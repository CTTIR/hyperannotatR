# Optional writer candidate and PNG reader boundary

An independent Python standard-library P5 payload can carry exact unsigned8/16-bit mask codes into magick without converting through 8-bit hexadecimal raster colours. On local magick2.9.1 / ImageMagick7.1.2.18, P5 input followed by image_write(format='tiff',depth=bits,compression='none') preserves bit depth and exact sample values for the recorded sixteen-bit matrix, all-zero, binary0/1 and maximum-value boundary arrays. Python tifffile independently decoded TIFF tags and values. This is a tested adapter candidate, not implemented package behavior.

PNG needs explicit format definitions: depth=bits alone optimizes all-zero and extrema-only examples into one-bit files. Adding defines=c('png:bit-depth'=as.character(bits),'png:color-type'='0') preserves the requested8/16-bit grayscale encoding and exact values for all tested boundary arrays. Python Pillow independently decodes the pixels; PNG IHDR bytes confirm depth and colour type. Files ending observed.json retain each outcome; boundary-probe.R and generate.py reproduce the candidate experiments.

The correctly written reference16-bit PNG also exposed A32 in the current mask reader. On the reviewed pre-T06 snapshot, raw rows `[0,1,255,256]` and `[4096,32767,32768,65535]` become `[0,0,1,1]` and `[16,127,128,255]` via magick::image_data(channels='gray'), and public at_read_mask succeeds with those wrong class codes. This silently loses foreground values and merges categories. T08 must qualify a raw8/16-bit grayscale input path or reject unsupported depth/type; TIFF fallback through the same8-bit path must also be prevented or fixed.

The [PGM specification](https://netpbm.sourceforge.net/doc/pgm.html) describes the P5 row order and unsigned big-endian two-byte samples used here. No display gamma operation was applied in the candidate chain; independent decoded output supplies the exact-value evidence.

A PNG decoder candidate also passes locally: image_read followed by image_write(format='pgm',depth=the_original_IHDR_depth) returns byte-identical P5 buffers to the independently packed originals for the reference matrix and all six constant/binary/extrema cases. The same exact result holds with no gamma tag and with gAMA values20000,100000,220000 on the reference16-bit PNG; independent Pillow decoding confirms unchanged source codes. See decoder-observed.json and gamma-observed.json. A production adapter still needs strict grayscale/depth validation and qualification of its actual ImageMagick build; do not assume8-bit-only builds preserve16-bit codes.
