The initial TIFF/OME/NPY reference files were written independently with NumPy 2.5.3 and tifffile 2026.9.9 in `/tmp/annotatr-roadmap-reference`. The first band has literal rows 111–115,121–125,131–135,141–145. T07 will preserve the reader fixtures and assertions; T12 extends the analytical reference inventory. These diagnostic observations are not passing regression tests.

RBioFormats 1.12.0 / Bio-Formats 7.3.0 became available in a temporary R library after installing development headers into a temporary directory. The existing system R and Java configuration was not changed. Availability alone does not qualify a reader: the orientation failure is an example of why exact-value interoperability checks are required.

A candidate terra/GDAL path also needs explicit image orientation: its default metadata open vertically flips the unreferenced TIFF in this fixture. The installed API supports `noflip=TRUE`; T07 and T15 must test the chosen adapters against the literal array.

Additional type probes narrow A26: grayscale uint16 reads raw values correctly, signed16 is misinterpreted as unsigned, and float32 errors under `as.is=TRUE`. A correction must distinguish sample type and color space; blanket scaling would damage the working grayscale path. No grayscale mask scaling defect is claimed from these observations.

A27 also affects automatic detection when RBioFormats is unavailable: the known three-band OME fixture silently falls through to the raster backend and returns one band/one level without wavelengths. T07 must preserve the declared axes and calibration or report the unavailable OME capability; generic display conversion must not masquerade as successful OME decoding.

A28 evidence: [signed export observations](evidence/implementation-2026-09-10/integer-export-baseline.md) and [raw values](evidence/implementation-2026-09-10/integer-export-baseline.json). A29 evidence: [writer tags and raw values](evidence/implementation-2026-09-10/mask-writer-fallback-baseline.json). A29 used a cloned helper environment solely to simulate absent tiff; it is a controlled optional-branch probe, not an actual minimal-installation qualification.

A26 also affects plain TIFF automatic fallback: with the tiff backend simulated unavailable, the same raw uint16 fixture is read through raster/uint8 and its first row 111–115 becomes `[0,1,1,0,0]`. [Recorded observation](evidence/implementation-2026-09-10/plain-tiff-detection-baseline.json). Automatic detection must preserve raw TIFF samples or explain the missing raw-reader capability; an explicitly selected raster conversion remains a separate display workflow.

A30 evidence: [ENVI boundary observations](evidence/implementation-2026-09-10/envi-int32-baseline.md) and [literal values and hashes](evidence/implementation-2026-09-10/envi-int32-baseline.json). This is separate from the NPY integer-mask contract: R double image arrays can exactly represent every signed int32 value.

A31 evidence: [actual QuPath consumer observations](evidence/implementation-2026-09-10/qupath-consumer-baseline.md). Outbound geometry/labels/colours/locks passed literal headless consumer assertions; native return-array import and colour recovery did not. Native UUID assignment also needs an explicit documented identifier mapping for a claimed external round trip.

A32 evidence and a qualified optional-writer candidate are in [mask depth probes](evidence/implementation-2026-09-10/mask-pgm-probe.md), with [literal PNG reader observations](evidence/implementation-2026-09-10/png16-reader-baseline.json). The candidate does not constitute an implemented fix.

A33 was discovered on the uncommitted implementation after T07, not on the original audited revision. The [public derivation and NPY observation](evidence/implementation-2026-09-10/metadata-key-observed.json) and [probe](evidence/implementation-2026-09-10/metadata-key-probe.R) confirm that R partial field matching can turn an unsupported near-prefix field into an authoritative reader contract. The diagnostic exits normally while reporting the incorrect verified result; it is not a passing correctness test. Exact key handling must preserve unknown metadata without interpreting it as a supported field.
