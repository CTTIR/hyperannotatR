# Independent reader fixtures

These tiny synthetic files contain no acquired, patient, or third-party image data.
They are generated independently of hyperannotatR by the adjacent Python generators.
Required generator versions: NumPy 2.5.3 and tifffile 2026.9.9 (Python 3).
The generated bytes and SHA-256 manifests are bundled together; mandatory R tests
consume these files directly and require neither Python nor a private workbench.

Run `python3 binary/generate.py` and `python3 images/generate.py` from this directory
in an environment with those dependencies. Each generator writes beside itself.
`sha256.json` in each subdirectory records all binary/header fixture hashes.
OME UUIDs are fixed so repeating either generator produces identical bytes.

The logical reference cube has shape y=4, x=5, band=3, and literal sample
`100 * (band + 1) + 10 * (y + 1) + x + 1` for zero-based indices. Its first
band rows are 111–115, 121–125, 131–135, 141–145. ENVI covers BSQ/BIL/BIP and
both byte orders with a 16-byte `HEADER_SENTINEL!` prefix and permitted trailing
metadata. Signed int32 ENVI boundary files preserve the quantitative INT_MIN.
NPY covers C/Fortran orientation and both-endian signed/unsigned integer bounds;
INT_MIN and wider out-of-range mask values must reject before integer coercion.
The SpecCube is a synthetic public format-contract fixture, not camera validation.

The OME cube has three named channels blue/green/red with emission wavelengths
450/550/650 nm and anisotropic physical pixels 0.5 by 2 micrometres. Its independent
pyramid has CYX shapes 3x48x64, 3x24x16 and 3x12x8; level 1 is sampled by y=2,x=4.
ZCYX and TCYX fixtures deliberately require a plane-selection error.
Grayscale/RGB TIFF files isolate dtype, signedness and normalisation; float32
contains negative/fractional/NaN/Inf values. Unsupported int32, uint32 and float64
TIFF files qualify explicit rejection by the minimal tiff reader.

References: NumPy's NPY format specification at
https://numpy.org/doc/stable/reference/generated/numpy.lib.format.html and ENVI
header fields at https://www.nv5geospatialsoftware.com/docs/enviheaderfiles.html.
The formula and literal tests are the pixel oracle; package writer round-trips
are supplementary persistence checks only.
